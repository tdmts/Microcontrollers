Automatisch rolluik met LDR en eindeloopschakelaars

Bouw een rolluik dat vanzelf omlaag gaat als het donker wordt en weer omhoog als het licht wordt. Twee drukknoppen spelen de eindeloopschakelaars die melden dat het luik boven of onder is, en op een LCD lees je af wat de sturing denkt.

Dit is de eindoefening van het labo, en ze brengt bijna alles samen: een spanningsdeler met een LDR uit labo 2, het I²C-display uit labo 4, en de H-brug uit dit labo. Twee dingen zijn nieuw, en die staan hieronder uitgelegd: hysteresis en draadbreukbeveiliging.

Wat het moet doen

  • Meet het omgevingslicht met een LDR in een spanningsdeler.
  • Toon op het LCD of het "donker" of "licht" is.
  • Wordt het donker, laat het rolluik dan traag omlaag gaan: de DC motor draait in wijzerzin tot knop 1 wordt ingedrukt.
  • Wordt het licht, laat het traag omhoog gaan: de motor draait in tegenwijzerzin tot knop 2 wordt ingedrukt.
  • Staat het luik al waar het moet zijn, dan gebeurt er niets.

De twee knoppen zijn gesimuleerde eindeloopschakelaars. In een echt rolluik zit er zo'n schakelaar boven en onder, en die vertellen de sturing dat het luik op het einde van zijn baan zit. Dat is dezelfde rol als de drukknop in de vorige oefening, waar een druk betekende "je bent aan het einde".

Traag betekent hier PWM

"Traag omlaag" regel je met analogWrite() op de enable van je H-brug, zoals in Zacht omkeren met de L293D. Een rolluik dat aan volle snelheid tegen zijn eindaanslag knalt, gaat stuk.

Hysteresis: waarom één drempel niet volstaat

Stel dat je zegt: onder de 500 is het donker, daarboven is het licht. Wat gebeurt er dan bij schemering, wanneer je meting rond die 500 blijft schommelen?

Je meet 499, dus donker, dus het luik gaat omlaag. Een lus later meet je 501, dus licht, dus het luik gaat omhoog. Dan weer 498. Je rolluik staat de hele avond op en neer te gaan tot er iets stukgaat. Een sensor die precies op de grens blijft hangen laat je sturing oscilleren.

De oplossing is om twee drempels te gebruiken in plaats van één, met een dode zone ertussen:

Meting Wat er gebeurt
onder de 450 Het is donker geworden, luik omlaag
tussen 450 en 550 Verander niets, blijf doen wat je deed
boven de 550 Het is licht geworden, luik omhoog

Het luik dat omlaag ging, blijft nu omlaag tot de meting écht boven de 550 komt. Kleine schommelingen rond de 500 halen die grens niet. Dat heet hysteresis, en het betekent dat de drempel waarop je iets aanzet niet op dezelfde plaats ligt als de drempel waarop je het weer uitzet.

Je kent dit al van je thermostaat

Zet je die op 20 graden, dan slaat de verwarming aan bij 19,5 en pas weer af bij 20,5. Zonder die marge zou de brander elke minuut aan- en uitspringen.

Wat als een knop stukgaat?

Denk nu na over het volgende. Je rolluik gaat omlaag en stopt wanneer knop 1 ingedrukt wordt. Wat gebeurt er als de draad naar die knop breekt, of als het contact vuil wordt en niet meer sluit?

De sturing krijgt nooit het signaal dat het luik beneden is, dus de motor blijft draaien. Het luik loopt tegen zijn aanslag, de motor blijft trekken en trekt daarbij zijn blokkeerstroom, en er begint iets te scheuren of te branden.

Het gevaarlijke is dat een gebroken draad er voor je programma hetzelfde uitziet als een knop die niet ingedrukt is. Je sturing heeft geen enkele manier om die twee uit elkaar te houden, en blijft dus doorlopen.

De oplossing zit niet in je code maar in je bedrading. Sluit een eindeloopschakelaar aan als verbreekcontact. In rust is het contact gesloten, en het gaat open wanneer het luik erop duwt.

Situatie Maakcontact (sluit bij bediening) Verbreekcontact (opent bij bediening)
Luik onderweg Geen signaal, motor draait door Signaal aanwezig, motor draait door
Luik op het einde Signaal, motor stopt Signaal weg, motor stopt
Draad gebroken Geen signaal, motor draait door: gevaarlijk Signaal weg, motor stopt: veilig

Met een verbreekcontact leidt elke storing, of dat nu een gebroken draad, een losse connector of een kapotte schakelaar is, tot dezelfde toestand als "einde bereikt". De installatie valt dan stil in plaats van door te lopen. Dat principe heet draadbreukbeveiliging, en je vindt het terug in zowat elke veiligheidskring: noodstoppen, deurcontacten en beveiligingen zijn bijna altijd verbreekcontacten.

Dit keert je logica om

Werk je met verbreekcontacten, dan betekent een ingang die hoog staat "alles in orde, je mag doorlopen", en een ingang die laag valt "stop". Dat is het omgekeerde van wat je gewend bent van een drukknop. Zet in je commentaar duidelijk welke keuze je gemaakt hebt, anders zoek je het over een week zelf niet meer terug.

Oplossing

De sturing houdt in toestand bij wat het luik aan het doen is. Je beslist dus niet elke lus opnieuw vanaf nul, maar wisselt tussen drie toestanden. Zo kan je hysteresis toepassen, want "blijf doen wat je deed" heeft alleen betekenis als je weet wát je deed.

De twee drempels doen de rest. Alleen onder drempelDonker of boven drempelLicht verandert er iets van toestand. In de zone ertussen blijft toestand onaangeroerd.

De eindeloopschakelaars zijn verbreekcontacten op INPUT_PULLUP, dus in rust lezen ze LOW omdat het gesloten contact ze aan de massa legt. Spreekt de schakelaar aan, of breekt de draad, dan trekt de pull-up de ingang HIGH en stopt de motor.

#include <Wire.h>
#include <LiquidCrystal_I2C.h>

const int enablePin = 3; // 1,2EN van de L293D, PWM-pin
const int in1Pin = 4;    // 1A
const int in2Pin = 5;    // 2A

const int ldrPin = A0;
const int eindeOnderPin = 6; // verbreekcontact: LOW zolang alles in orde is
const int eindeBovenPin = 7; // verbreekcontact

const int adresLcd = 0x20;
LiquidCrystal_I2C lcd(adresLcd, 16, 2);

// Twee drempels, met een dode zone ertussen. Dat is de hysteresis.
const int drempelDonker = 450;
const int drempelLicht = 550;

const int traagheid = 120; // PWM-waarde, ruim onder voluit

// De drie toestanden waarin het rolluik kan zitten
const int STIL = 0;
const int OMLAAG = 1;
const int OMHOOG = 2;

// Wat de LDR ons vertelt
const int DONKER = 0;
const int LICHT = 1;

int toestand = STIL;

// Wat er nu op het scherm staat, zodat we niet elke ronde herschrijven.
int getoondeToestand = -1;
int getoondLicht = -1;

void zetMotor(int richting)
{
  if (richting == OMLAAG)
  {
    digitalWrite(in1Pin, HIGH);
    digitalWrite(in2Pin, LOW);
    analogWrite(enablePin, traagheid);
  }
  else if (richting == OMHOOG)
  {
    digitalWrite(in1Pin, LOW);
    digitalWrite(in2Pin, HIGH);
    analogWrite(enablePin, traagheid);
  }
  else
  {
    analogWrite(enablePin, 0);
  }
}

void setup()
{
  pinMode(enablePin, OUTPUT);
  pinMode(in1Pin, OUTPUT);
  pinMode(in2Pin, OUTPUT);

  pinMode(eindeOnderPin, INPUT_PULLUP);
  pinMode(eindeBovenPin, INPUT_PULLUP);

  lcd.init();
  lcd.backlight();
}

void loop()
{
  int licht = analogRead(ldrPin);
  int lichtStatus = getoondLicht; // in de dode zone verandert er niets

  // Alleen buiten de dode zone verandert er iets.
  if (licht < drempelDonker)
  {
    lichtStatus = DONKER;
    toestand = OMLAAG;
  }
  else if (licht > drempelLicht)
  {
    lichtStatus = LICHT;
    toestand = OMHOOG;
  }

  // Een verbreekcontact leest HIGH zodra het aanspreekt of de draad breekt.
  if (toestand == OMLAAG && digitalRead(eindeOnderPin) == HIGH)
  {
    toestand = STIL;
  }

  if (toestand == OMHOOG && digitalRead(eindeBovenPin) == HIGH)
  {
    toestand = STIL;
  }

  zetMotor(toestand);

  // Alleen naar het scherm schrijven als er echt iets veranderd is.
  if (lichtStatus != getoondLicht)
  {
    lcd.setCursor(0, 0);

    if (lichtStatus == DONKER)
    {
      lcd.print("Het is donker  ");
    }
    else
    {
      lcd.print("Het is licht   ");
    }

    getoondLicht = lichtStatus;
  }

  if (toestand != getoondeToestand)
  {
    lcd.setCursor(0, 1);

    if (toestand == OMLAAG)
    {
      lcd.print("Luik omlaag    ");
    }
    else if (toestand == OMHOOG)
    {
      lcd.print("Luik omhoog    ");
    }
    else
    {
      lcd.print("Luik staat stil");
    }

    getoondeToestand = toestand;
  }

  delay(100);
}
Twee dingen aan het scherm

De spaties achter de tekst. Een LCD wist zichzelf niet. Schrijf je "Het is licht" over "Het is donker" heen, dan blijft de r van donker staan en lees je "Het is lichtr". Door elke regel aan te vullen tot de volle breedte overschrijf je wat er stond.

De twee variabelen getoondLicht en getoondeToestand. Die houden bij wat er al op het scherm staat, zodat je alleen schrijft als er echt iets verandert. Dat is dezelfde reden als in labo 4, waar de tekst in de setup() stond, want een LCD dat je blijft herschrijven gaat flikkeren. Hier kan de tekst wel veranderen, dus verhuist de regel van "schrijf één keer" naar "schrijf alleen bij verandering".
