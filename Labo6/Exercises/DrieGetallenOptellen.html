Drie getallen doorsturen en optellen

Arduino 1 verzint drie willekeurige getallen en stuurt ze door. Arduino 2 leest ze in, telt ze op, en toont de drie getallen met hun som in de seriële monitor.

Tot nu toe stond er altijd maar één soort waarde op de lijn. Zodra er meerdere waarden achter elkaar komen, duikt er een nieuw probleem op, want de ontvanger moet weten welke van de drie hij aan het lezen is. Deze oefening laat je dat probleem zelf tegenkomen. In de volgende oefening los je het op.

Deze oefening werk je uit in TinkerCAD. Je hebt alleen de drie seriële draden nodig, verder geen componenten.

Het schema

Wat je moet programmeren

  1. Arduino 1 maakt drie willekeurige getallen met random(), elk tussen 0 en 999, en stuurt ze door. Daarna wacht hij een paar seconden en begint opnieuw.
  2. Arduino 2 leest drie getallen in, telt ze op, en schrijft de drie getallen en hun som naar zijn seriële monitor.

Stuur elk getal op zijn eigen lijn, dus met een aparte Serial.println(). Zet je ze achter elkaar met print(), dan komt er aan de overkant 123456789 binnen en is er geen manier meer om te weten waar het ene getal ophoudt en het volgende begint.

random() begint elke keer op dezelfde plaats

random() rekent een reeks uit die altijd dezelfde is als je op hetzelfde punt begint. Na elke reset krijg je dus dezelfde drie getallen. Met randomSeed() in je setup() geef je die reeks een ander vertrekpunt. De klassieke truc is randomSeed(analogRead(A5)) met een pin waar niets aan hangt, want die pikt ruis op.

In TinkerCAD levert zo'n losse pin soms wel elke keer dezelfde waarde op, en dan blijft je reeks toch hetzelfde. Dat is geen fout in je programma, en voor deze oefening maakt het niets uit.

De bovengrens van random() valt erbuiten

De bovengrens die je meegeeft doet zelf niet mee. random(0, 1000) geeft je dus een getal van 0 tot en met 999. Wil je 1000 er wel bij, dan schrijf je random(0, 1001).

Haal het bewust uit de pas

Als je programma werkt, doe dan nog deze proef. Laat de twee Arduino's lopen en druk halverwege een reeks op de resetknop van Arduino 2, of start alleen de ontvanger opnieuw op.

Kijk daarna goed naar wat er in de monitor verschijnt. De kans is groot dat de som niet meer klopt met de getallen die de zender verstuurt, en dat het zo blijft. De ontvanger telt verder in de veronderstelling dat het volgende getal het eerste van een nieuwe reeks is, terwijl hij in het midden ingestapt is. Hij merkt daar zelf niets van.

Oplossing

Bij de ontvanger staat het lezen van één getal in een aparte functie. Zo blijft de loop() leesbaar, want er staat "lees a, lees b, lees c". Zonder die functie zou je driemaal hetzelfde blok code onder elkaar hebben staan.

Die functie blijft wachten tot er iets binnenkomt. Dat mag hier, want de ontvanger heeft toch niets anders te doen.

Arduino 1, de zender:

void setup()
{
  Serial.begin(9600);

  randomSeed(analogRead(A5)); // A5 hangt nergens aan en pikt ruis op
}

void loop()
{
  Serial.println(random(0, 1000));
  Serial.println(random(0, 1000));
  Serial.println(random(0, 1000));

  delay(3000);
}

Arduino 2, de ontvanger:

void setup()
{
  Serial.begin(9600);
}

int leesGetal()
{
  while (Serial.available() == 0)
  {
    // wacht tot er een boodschap binnenkomt
  }

  String regel = Serial.readStringUntil('\n');
  regel.trim();

  return regel.toInt();
}

void loop()
{
  int a = leesGetal();
  int b = leesGetal();
  int c = leesGetal();

  Serial.print(a);
  Serial.print(" + ");
  Serial.print(b);
  Serial.print(" + ");
  Serial.print(c);
  Serial.print(" = ");
  Serial.println(a + b + c);
}

Dit programma heeft één zwakke plek. Nergens staat welk getal het eerste van een reeks is. De ontvanger neemt aan dat het volgende dat binnenkomt de a is. Stap hij op het verkeerde moment in, dan schuift alles één plaats op en blijft dat zo, want er is niets dat hem ooit weer op het juiste spoor zet.
