Drie soorten boodschappen uit elkaar houden

Er komen temperaturen, windrichtingen en vochtigheden door elkaar binnen, op onvoorspelbare momenten. Toch weet je ontvanger van elke boodschap wat ze voorstelt, omdat er een sleutel voor staat.

De vorige oefening liep vast op één punt, want de ontvanger moest tellen om te weten wat hij aan het lezen was, en zodra hij zich één keer misteld had, kwam dat nooit meer goed. De oplossing is dat elke boodschap zelf zegt wat ze is.

In deze oefening ziet een boodschap er zo uit:

TEMP:20.5
WIND:124
HUMIDITY:55

Eerst een sleutel, dan een dubbelepunt, dan de waarde. Hoe je zo'n lijn uit elkaar haalt staat op Werken met een String. Lees dat eerst, want daar staat het recept dat je hier gaat toepassen.

Deze oefening werk je uit in TinkerCAD. Je hebt de drie seriële draden nodig, en een potentiometer op Arduino 1.

Het schema

Dezelfde opstelling als de vorige oefening, met de potentiometer van oefening 4 terug op A0 van Arduino 1. Arduino 2 schrijft alleen naar zijn eigen monitor, dus daar hangt niets aan.

Wat je moet programmeren

Arduino 1 speelt voor weerstation. Er zijn geen drie echte sensoren, dus doe je alsof. Lees de potentiometer uit, en stuur die ene waarde afwisselend door als temperatuur, als windrichting of als vochtigheid. Welke van de drie het wordt, laat je aan het toeval over met random(), en tussen twee boodschappen wacht je een willekeurige tijd. Zo komen ze net zo onregelmatig binnen als bij echte sensoren.

De drie boodschappen
Sleutel Wat het voorstelt Bereik Voorbeeld
TEMP Temperatuur in graden Celsius, tot op een tiende nauwkeurig -20,0 tot 60,0 TEMP:20.5
WIND Windrichting als hoek, waarbij 0 het noorden is 0 tot 359 WIND:124
HUMIDITY Relatieve luchtvochtigheid in hele procenten 0 tot 100 HUMIDITY:55

Arduino 2 leest elke lijn in, splitst ze op de dubbelepunt, kijkt met een if welke sleutel het is en toont dan een nette zin in zijn monitor. Bijvoorbeeld Temperatuur: 20.5 C of Windrichting: 124 graden.

Zet de waarde pas om als je de sleutel kent

Bij TEMP hoort een kommagetal, bij de twee andere een geheel getal. Je kan dus onmogelijk op voorhand beslissen of je toFloat() of toInt() gebruikt. Splits eerst, kijk dan welke sleutel het is, en zet pas daarna om.

Controleer eerst wat er binnenkomt

indexOf(':') geeft je -1 als er geen dubbelepunt in de lijn staat. Ga je daar toch mee verder rekenen, dan knip je op een plaats die niet bestaat. Op een seriële lijn komt er vroeg of laat rommel binnen, dus controleer dat eerst. En zet er een else bij voor een sleutel die je niet kent, zodat je ziet dat er iets binnenkomt dat je niet verwachtte in plaats van dat het spoorloos verdwijnt.

Probeer de proef van vorige keer opnieuw

Reset Arduino 2 nu nog eens midden in het verkeer. Deze keer pikt hij de eerstvolgende volledige lijn op en klopt alles weer. Er valt hoogstens één halve boodschap weg, en de rest komt correct binnen.

Oplossing

Bij de zender doet map() al het werk. De temperatuur is het enige geval waar je moet opletten. map() rekent met gehele getallen, dus je schaalt eerst naar -200 tot 600 en deelt daarna door 10.0 om er tienden van te maken. Die .0 is belangrijk, want / 10 zou weer een geheel getal geven.

De 1 achter de waarde in Serial.println(temperatuur, 1) zegt hoeveel cijfers er na de komma moeten. Zonder dat krijg je er standaard twee.

Arduino 1, het weerstation:

const int potPin = A0;

void setup()
{
  Serial.begin(9600);

  randomSeed(analogRead(A5));
}

void loop()
{
  int ruw = analogRead(potPin); // 0 tot 1023
  int soort = random(0, 3);     // 0, 1 of 2

  if (soort == 0)
  {
    // map() rekent met gehele getallen, dus eerst in tienden van een graad
    float temperatuur = map(ruw, 0, 1023, -200, 600) / 10.0;

    Serial.print("TEMP:");
    Serial.println(temperatuur, 1);
  }
  else if (soort == 1)
  {
    int richting = map(ruw, 0, 1023, 0, 359);

    Serial.print("WIND:");
    Serial.println(richting);
  }
  else
  {
    int vochtigheid = map(ruw, 0, 1023, 0, 100);

    Serial.print("HUMIDITY:");
    Serial.println(vochtigheid);
  }

  delay(random(1000, 3000)); // onregelmatig, zoals echte sensoren
}

Arduino 2, de ontvanger:

void setup()
{
  Serial.begin(9600);
}

void loop()
{
  if (Serial.available() > 0)
  {
    String regel = Serial.readStringUntil('\n');
    regel.trim();

    int scheiding = regel.indexOf(':');

    if (scheiding > 0) // zonder dubbelepunt is het geen geldige boodschap
    {
      String sleutel = regel.substring(0, scheiding);
      String waarde = regel.substring(scheiding + 1);

      if (sleutel == "TEMP")
      {
        Serial.print("Temperatuur: ");
        Serial.print(waarde.toFloat(), 1);
        Serial.println(" C");
      }
      else if (sleutel == "WIND")
      {
        Serial.print("Windrichting: ");
        Serial.print(waarde.toInt());
        Serial.println(" graden");
      }
      else if (sleutel == "HUMIDITY")
      {
        Serial.print("Vochtigheid: ");
        Serial.print(waarde.toInt());
        Serial.println(" %");
      }
      else
      {
        Serial.print("Onbekende sleutel: ");
        Serial.println(sleutel);
      }
    }
  }
}

Deze ontvanger maakt geen enkele veronderstelling over de volgorde. Er mogen tien temperaturen na elkaar komen, of nooit meer een windrichting, want elke lijn wordt beoordeeld op wat erin staat.
