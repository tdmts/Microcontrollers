Een potentiometerwaarde doorsturen en dimmen

De potentiometer zit op Arduino 1, de led op Arduino 2. Draai je aan de knop, dan verandert de helderheid van een led die aan een heel andere Arduino hangt.

De vorige oefening stuurde alleen aan of uit door. Nu stuur je een gemeten waarde. Een meting verandert voortdurend een klein beetje, dus je moet nadenken over hoe vaak je iets doorstuurt. Alles wat je hiervoor nodig hebt aan analoge in- en uitgangen ken je al uit analogRead(), analogWrite() en map().

Deze oefening werk je uit in TinkerCAD. Vertrek van de bedrading uit de vorige oefening.

Het schema

Wat er bij komt bovenop de seriële verbinding
Arduino Aansluiting Waarvoor
Arduino 1 A0 De loper van de potentiometer. De buitenste pootjes gaan naar 5 V en GND.
Arduino 2 pin 3 De led, via een weerstand van 220 Ω
De led moet op een pin met een ~

Je gaat de helderheid regelen met analogWrite(), en dat werkt alleen op een pin met PWM. Op de UNO staat daar een tilde bij: 3, 5, 6, 9, 10 en 11. Hang je de led op pin 4, dan gaat ze wel aan en uit, maar dimmen doet ze niet.

Wat je moet programmeren

  1. Arduino 1 leest de potentiometer uit met analogRead() en stuurt die waarde door.
  2. Arduino 2 leest de lijn, maakt er met toInt() weer een getal van, schaalt dat met map() naar het bereik van analogWrite() en stuurt het naar de led.

Let op de twee bereiken. analogRead() geeft je 0 tot 1023, terwijl analogWrite() maar 0 tot 255 aankan. Die omrekening moet ergens gebeuren. Doe ze bij de ontvanger, want dan blijft er op de lijn staan wat er echt gemeten is en niet al een half verwerkt getal.

Kies zelf hoe vaak je zendt. Te traag en je led loopt zichtbaar achter op je vinger, te snel en je loopt de buffer over. Ergens tussen twintig en vijftig keer per seconde is ruim genoeg.

Waarom zenden zonder pauze mis loopt

Bij 9600 baud passen er ongeveer 960 tekens per seconde over de draad. Een waarde als 1023 plus het regeleinde is al zes tekens, dus je zit rond de 160 boodschappen per seconde als absolute bovengrens. Je loop() draait er duizenden. Zonder delay() stop je er dus meer in dan er uit kan, de buffer van 64 bytes loopt over, en je led loopt seconden achter terwijl het lijkt alsof je programma traag is.

Oplossing

De delay(50) bij de zender geeft twintig boodschappen per seconde. Dat is ruim binnen wat de lijn aankan en veel sneller dan je oog het verschil ziet.

Arduino 1, met de potentiometer:

const int potPin = A0;

void setup()
{
  Serial.begin(9600);
}

void loop()
{
  int waarde = analogRead(potPin); // 0 tot 1023

  Serial.println(waarde);

  delay(50); // twintig keer per seconde is ruim genoeg
}

Arduino 2, met de led:

const int ledPin = 3;

void setup()
{
  pinMode(ledPin, OUTPUT);

  Serial.begin(9600);
}

void loop()
{
  if (Serial.available() > 0)
  {
    String regel = Serial.readStringUntil('\n');
    regel.trim();

    int waarde = regel.toInt();
    int helderheid = map(waarde, 0, 1023, 0, 255);

    analogWrite(ledPin, helderheid);
  }
}

Komt er ooit iets binnen dat geen getal is, dan geeft toInt() je 0 en gaat de led even uit. Dat is hier onschuldig. Vanaf de volgende oefening wordt het dat niet meer, en dan pak je het aan.
