Werken met bits

De PCF8574 stuurt acht pinnen tegelijk aan met één byte. Je kan dus niet één pin apart aanspreken: je leest en schrijft altijd alle acht samen. Om toch met één pin te kunnen werken heb je een paar operatoren nodig die je in de vorige labo's nog niet gebruikt hebt.

Een byte is acht bits

Een byte bestaat uit 8 bits, en elke bit is 0 of 1. Bij de PCF8574 hoort elke bit bij één pin. De rechtse bit is P0, de linkse is P7:

De byte B00100110 pin per pin
P7 P6 P5 P4 P3 P2 P1 P0
0 0 1 0 0 1 1 0

Die bit helemaal rechts noemen we bit 0, de volgende bit 1, en zo verder tot bit 7. De nummers van de bits komen dus overeen met de nummers van de pinnen, en dat is geen toeval.

Drie schrijfwijzen voor dezelfde waarde

Je mag een byte in je code op drie manieren schrijven. Ze betekenen exact hetzelfde, de compiler maakt er geen onderscheid tussen:

byte a = B00100110; // binair: je ziet elke bit staan
byte b = 0x26;      // hexadecimaal
byte c = 38;        // decimaal
Kies de schrijfwijze die je code leesbaar maakt

Gaat het over welke pin aan of uit staat, gebruik dan binair. In B11111110 zie je meteen dat enkel P0 laag staat. In 0xFE moet je dat eerst omrekenen. Gaat het over een gewoon getal, dan is decimaal natuurlijk duidelijker.

De operatoren

Deze vier operatoren werken bit per bit. Ze rekenen niet met de waarde van de byte als geheel, maar zetten bit 0 tegenover bit 0, bit 1 tegenover bit 1, enzovoort.

De bitoperatoren die je in dit labo nodig hebt
Operator Naam Wat ze doet
& AND Een bit in het resultaat is 1 als hij in beide operanden 1 is.
| OR Een bit in het resultaat is 1 als hij in minstens één van beide operanden 1 is.
~ NOT Keert elke bit om: elke 0 wordt 1 en elke 1 wordt 0.
<< schuiven naar links Schuift alle bits een aantal plaatsen naar links. Rechts komen nullen bij.
Verwar & niet met &&

&& is de logische EN die je in een if gebruikt: die kijkt naar twee voorwaarden als geheel en levert waar of niet waar op. & met één teken werkt bit per bit en levert een byte op. Datzelfde verschil bestaat tussen | en ||. Eén teken te veel of te weinig compileert vaak gewoon, en dan zoek je lang.

Eén bit uitlezen: maskeren

Je leest de hele byte in, maar je wil weten hoe het met één bepaalde pin gesteld is. Daarvoor gebruik je een masker: een byte waarin enkel de bit staat waarin je geïnteresseerd bent. Met & houd je van de ingelezen waarde alleen die ene bit over, want overal waar het masker 0 staat wordt het resultaat sowieso 0.

byte waarde = B01010101; // wat we van de chip lazen

bool bit0 = waarde & B00000001; // 1, want de rechtse bit van waarde is 1
bool bit1 = waarde & B00000010; // 0, want de tweede bit van waarde is 0

Uitgeschreven voor bit1:

B01010101 & B00000010
waarde 01010101
masker 00000010
resultaat 00000000

Het resultaat is 0, dus die bit stond laag. Merk op dat het resultaat van zo'n maskering niet 1 hoeft te zijn wanneer de bit hoog staat: waarde & B00000010 levert bij een hoge bit de waarde 2 op, niet 1. Voor een bool of een if maakt dat niets uit, want alles wat niet 0 is telt als waar.

Bij een pull-upweerstand is ingedrukt een 0

Wil je expliciet weten of een knop ingedrukt is, schrijf dan de vergelijking er voluit bij. Dat leest een stuk duidelijker dan een omgekeerde bool:

bool knop1 = (waarde & B00000001) == 0;

Een masker berekenen met <<

Zolang je de maskers zelf uitschrijft is er niets aan de hand. Maar zodra je in een lus werkt, ken je het bitnummer pas terwijl je programma loopt. Dan bereken je het masker met <<: je vertrekt van een 1 helemaal rechts en schuift ze zoveel plaatsen naar links als je nodig hebt.

1 << 0  // B00000001, de bit van P0
1 << 1  // B00000010, de bit van P1
1 << 5  // B00100000, de bit van P5

1 << n is dus het masker van bit n, en daarmee kan je in een lus elke pin apart aanspreken.

Eén bit aanpassen zonder de rest te raken

Je schrijft altijd de hele byte naar de chip, dus wil je één bit veranderen en de zeven andere laten staan. Met OR zet je een bit op 1, met AND van het omgekeerde masker zet je hem op 0:

byte patroon = B11111111;

patroon = patroon | (1 << 2);  // bit 2 op 1 zetten
patroon = patroon & ~(1 << 3); // bit 3 op 0 zetten

Die tweede regel lees je van binnen naar buiten. 1 << 3 is B00001000, het masker van bit 3. ~ keert dat om tot B11110111: overal een 1 behalve op de plaats van bit 3. Doe je daar een AND mee, dan blijft elke andere bit gewoon zichzelf, en wordt enkel bit 3 gegarandeerd 0.

Omdat je het resultaat meestal in dezelfde variabele terugstopt, mag je dat korter schrijven. a &= b betekent precies hetzelfde als a = a & b, net zoals a += b hetzelfde is als a = a + b:

patroon |= (1 << 2);  // bit 2 op 1
patroon &= ~(1 << 3); // bit 3 op 0

Alle bits vergelijken in één keer

Een laatste patroon dat je in dit labo tegenkomt: nagaan welke knoppen net ingedrukt zijn. Een knop die je ingedrukt houdt, blijft immers doorlopend een 0 geven, waardoor je programma denkt dat je tientallen keren per seconde drukt.

Bewaar daarvoor de vorige byte, en zoek de bits die van 1 naar 0 gegaan zijn:

byte netIngedrukt = ~knoppen & vorigeKnoppen;

~knoppen heeft een 1 staan op elke plaats waar een knop nu ingedrukt is. vorigeKnoppen heeft een 1 staan op elke plaats waar een knop vorige keer los was. Een AND van die twee houdt dus precies de knoppen over die deze doorloop van los naar ingedrukt gegaan zijn. Alle acht de knoppen worden daarbij in één bewerking behandeld.
