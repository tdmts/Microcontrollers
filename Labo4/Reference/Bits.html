Werken met bits

Een byte is één getal, en tegelijk acht losse bits die elk 0 of 1 zijn. De PCF8574 geeft zijn acht pinnen door als één byte, met elke bit op één pin, dus je leest en schrijft ze altijd alle acht samen. Om toch met één pin te kunnen werken, moet je met één bit kunnen werken: er één uit de byte halen, of er één in aanpassen. C++ heeft daarvoor operatoren die bit per bit rekenen in plaats van met een byte als geheel. Onder elke uitleg staan een paar vragen om het meteen te proberen.

Een byte is acht bits

Een byte houdt een geheel getal bij van 0 tot en met 255. In het geheugen staat dat getal als acht bits, en elke bit is 0 of 1. Die 256 mogelijke waarden zijn precies het aantal combinaties dat je met acht bits kan maken.

De bit helemaal rechts noemen we bit 0, de volgende bit 1, en zo verder tot bit 7 helemaal links. Elke bit heeft een plaatswaarde die telkens verdubbelt, en de waarde van de byte is de som van de plaatswaarden waar een 1 staat:

De byte B00100110 uitgeschreven
bit 7 bit 6 bit 5 bit 4 bit 3 bit 2 bit 1 bit 0
plaatswaarde 1286432168421
B00100110 00100110

Hier staan er drie bits hoog: bit 5, bit 2 en bit 1. Tel hun plaatswaarden op en je hebt de waarde van de byte.

Reken uit: welke decimale waarde heeft B00100110?

De hoge bits zijn bit 5, bit 2 en bit 1. Hun plaatswaarden lees je af in de tabel: 32, 4 en 2. De waarde is dus 32 + 4 + 2 = 38.

Andersom: welke bits staan hoog in de byte 200?

Neem telkens de grootste plaatswaarde die er nog in past. 128 past in 200 en laat 72 over, 64 past in 72 en laat 8 over, en 8 past precies. Hoog staan dus bit 7, bit 6 en bit 3, oftewel B11001000.

Drie schrijfwijzen voor dezelfde waarde

Je mag een byte in je code op drie manieren schrijven. Ze betekenen exact hetzelfde, en de compiler maakt er geen onderscheid tussen:

byte a = B00100110; // binair: je ziet elke bit staan
byte b = 0x26;      // hexadecimaal
byte c = 38;        // decimaal

Dat is drie keer dezelfde byte als in de tabel hierboven. De binaire schrijfwijze begint met een hoofdletter B en daarachter staan de acht bits, van bit 7 tot bit 0. Hexadecimaal begint met 0x en is een compactere notatie die je vaak in datasheets en in adressen tegenkomt. Decimaal is het gewone getal.

Kies de schrijfwijze die je code leesbaar maakt

Gaat het over welke bit hoog of laag staat, gebruik dan binair. In B11111110 zie je meteen dat enkel bit 0 laag staat. In 0xFE en in 254 moet je dat eerst omrekenen. Gaat het over een gewoon getal, dan is decimaal duidelijker.

Schrijf op: een byte waarin enkel bit 4 hoog staat

byte masker = B00010000; Je mag 0x10 of 16 schrijven en de compiler doet exact hetzelfde, maar dan moet je bij het lezen zelf omrekenen welke bit je bedoelde.

De operatoren

Deze vier operatoren werken bit per bit. Ze rekenen niet met de waarde van de byte als geheel, maar zetten bit 0 tegenover bit 0, bit 1 tegenover bit 1, enzovoort.

De bitoperatoren
Operator Naam Wat ze doet
& AND Een bit in het resultaat is 1 als hij in beide operanden 1 is.
| OR Een bit in het resultaat is 1 als hij in minstens één van beide operanden 1 is.
~ NOT Keert elke bit om: elke 0 wordt 1 en elke 1 wordt 0.
<< schuiven naar links Schuift alle bits een aantal plaatsen naar links. Rechts komen nullen bij.
Verwar & met &&

&& is de logische EN die je in een if gebruikt: die kijkt naar twee voorwaarden als geheel en levert waar of niet waar op. & met één teken werkt bit per bit en levert een byte op. Datzelfde verschil bestaat tussen | en ||. Eén teken te veel of te weinig compileert vaak gewoon, en de fout is dan moeilijk terug te vinden.

Reken uit: B11001010 & B01101100

Zet de twee bytes onder elkaar en werk kolom per kolom. Alleen waar in beide rijen een 1 staat, komt er een 1 in het resultaat.

B11001010 11001010
B01101100 01101100
resultaat 01001000

Het resultaat is B01001000.

Reken uit: B11001010 | B01101100

Dezelfde twee bytes, maar nu volstaat één 1 in een kolom.

B11001010 11001010
B01101100 01101100
resultaat 11101110

Het resultaat is B11101110. Vergelijk kolom voor kolom met de tabel hierboven: AND en OR geven een ander antwoord in precies die kolommen waar één van beide rijen een 1 heeft.

Reken uit: ~B11001010

NOT heeft maar één operand, terwijl de andere drie er twee nodig hebben. Elke bit keert om.

B11001010 11001010
resultaat 00110101

Het resultaat is B00110101.

In de voorwaarde hieronder zit een fout. De bedoeling was te testen of bit 2 van waarde hoog staat. Zoek eerst zelf wat er misloopt:

if (waarde && B00000100)
{
    // ...
}
Wat loopt er mis in die voorwaarde?

Hier staat de logische EN (&&) in plaats van de bitoperator (&). B00000100 is de waarde 4 en dus altijd waar, waardoor deze voorwaarde klopt zodra waarde zelf niet 0 is, ongeacht welke bit hoog staat. Bedoeld was if (waarde & B00000100). Deze code compileert zonder warnings of errors. Let dus goed op!

Eén bit uitlezen: maskeren

Je hebt een byte en je wil weten hoe het met één bepaalde bit gesteld is. Daarvoor gebruik je een masker: een byte waarin enkel de bit hoog staat waarin je geïnteresseerd bent. Met & houd je van de oorspronkelijke waarde alleen die ene bit over, want overal waar het masker 0 staat wordt het resultaat sowieso 0.

byte waarde = B01010101;

bool bit0 = waarde & B00000001; // waar, want bit 0 van waarde is 1
bool bit1 = waarde & B00000010; // niet waar, want bit 1 van waarde is 0

if (bit0 == true)
{
    // bit 0 staat hoog
}

if (bit1 == false)
{
    // bit 1 staat laag
}

Uitgeschreven voor bit1:

B01010101 & B00000010
waarde 01010101
masker 00000010
resultaat 00000000

Het resultaat is 0, dus die bit stond laag. Merk op dat het resultaat van zo'n maskering niet 1 hoeft te zijn wanneer de bit hoog staat: waarde & B00000010 levert bij een hoge bit de waarde 2 op, en een masker van bit 5 levert 32 op.

Je hoeft de bit niet eerst in een aparte bool te zetten. De maskering mag ook rechtstreeks in de vergelijking staan, en dan moet je er zelf haakjes rond zetten:

bool bit0Laag = (waarde & B00000001) == 0;

Lees de code hieronder en bepaal wat er in bit4 en in bit6 terechtkomt:

byte waarde = B10110100;

bool bit4 = waarde & B00010000;
bool bit6 = waarde & B01000000;
Wat staat er in bit4 en in bit6?

Zet waarde en het masker onder elkaar en werk kolom per kolom. Voor bit4:

waarde 10110100
B00010000 00010000
resultaat 00010000

Er blijft een bit over, dus bit4 is waar. Merk op dat het resultaat 16 is en niet 1, want de bit staat op de plaats met plaatswaarde 16. Bij het opslaan in een bool wordt dat true, want alles wat niet 0 is telt als waar.

En voor bit6:

waarde 10110100
B01000000 01000000
resultaat 00000000

Het masker wijst bit 6 aan, en die staat in waarde op 0. Er blijft dus niets over en bit6 is niet waar.

Eén bit aanpassen terwijl de rest blijft staan

Vaak wil je één bit veranderen en de zeven andere ongemoeid laten, bijvoorbeeld omdat je de hele byte in één keer wegschrijft. Twee eigenschappen van de operatoren maken dat mogelijk:

  • Bij OR blijft een bit zichzelf tegenover een 0, en wordt hij 1 tegenover een 1. Een masker met één 1 zet dus precies die ene bit en laat de rest staan.
  • Bij AND blijft een bit zichzelf tegenover een 1, en wordt hij 0 tegenover een 0. Een masker met één 0 wist dus precies die ene bit en laat de rest staan.

Om bit 2 op 1 te zetten heb je dus een masker nodig met enkel bit 2 hoog: B00000100. Om bit 3 op 0 te zetten heb je er net het omgekeerde van nodig, overal een 1 behalve op de plaats van bit 3: B11110111. In stappen uitgeschreven:

byte patroon = B10011010;

// bit 2 op 1 zetten
byte maskerBit2 = B00000100;
byte patroonMetBit2 = patroon | maskerBit2; // B10011110

// bit 3 op 0 zetten
byte maskerBit3 = B11110111;
byte patroonZonderBit3 = patroon & maskerBit3; // B10010010

Dat tweede masker kan je ook door de compiler laten uitrekenen met ~: ~B00001000 is B11110111. Dan schrijf je op welke bit je bedoelt, en keer je dat om.

Beide bewerkingen vertrekken van dezelfde patroon, zodat je ze naast elkaar kan leggen:

Bit 2 zetten en bit 3 wissen, allebei op B10011010
bit 7 bit 6 bit 5 bit 4 bit 3 bit 2 bit 1 bit 0
patroon 10011010
masker B00000100 00000100
patroon | B00000100 10011110
masker B11110111 11110111
patroon & B11110111 10010010

In beide resultaatrijen zijn de zeven andere bits identiek aan die van patroon. Alleen de bit die het masker aanwijst is veranderd: bit 2 ging van 0 naar 1, bit 3 van 1 naar 0.

Schrijf één regel die bit 5 van patroon op 1 zet

patroon = patroon | B00100000; Stond bit 5 al hoog, dan verandert er niets, want een 1 tegenover een 1 blijft 1. Dat is de bedoeling: je zet de bit, je keert hem niet om.

En één regel die bit 0 op 0 zet

patroon = patroon & B11111110; Overal een 1 behalve op de plaats van bit 0. Je mag ook patroon = patroon & ~B00000001; schrijven, wat hetzelfde masker oplevert maar de bit noemt die je bedoelt.

In de regel hieronder zit een fout. Het commentaar zegt wat de bedoeling was:

patroon = patroon & B00001000; // bit 3 op 0 zetten
Wat loopt er mis in die regel?

Het masker is niet omgekeerd: er staat B00001000 waar B11110111 moest staan. Dit masker heeft één 1 en zeven nullen, en volgens de tweede vuistregel wist een AND dan die zeven bits en laat hij bit 3 staan zoals hij was. Dat is precies het omgekeerde van de bedoeling. Correct is patroon = patroon & B11110111;.

De verkorte schrijfwijze

Omdat je het resultaat meestal in dezelfde variabele terugstopt, mag je die korter schrijven. a &= b betekent precies hetzelfde als a = a & b, net zoals a += b hetzelfde is als a = a + b.

patroon |= B00000100; // bit 2 op 1
patroon &= B11110111; // bit 3 op 0

Zien welke bits veranderd zijn

Soms wil je niet weten hoe een byte er nu uitziet, maar wat er sinds de vorige keer veranderd is. Bewaar daarvoor de vorige waarde in een aparte variabele, en vergelijk. Ook dat gaat voor alle acht de bits in één bewerking:

byte vorige = B00110101;
byte huidige = B00011100;

byte naarNul = ~huidige & vorige;  // bits die van 1 naar 0 gingen
byte naarEen = huidige & ~vorige;  // bits die van 0 naar 1 gingen

~huidige heeft een 1 op elke plaats waar de bit nu laag is. Een AND met vorige houdt daarvan de bits over die vorige keer hoog waren:

naarNul = ~huidige & vorige
bit 7 bit 6 bit 5 bit 4 bit 3 bit 2 bit 1 bit 0
vorige 00110101
huidige 00011100
~huidige 11100011
naarNul 00100001

Bit 5 en bit 0 blijven over: dat zijn de twee die van 1 naar 0 gingen. De tweede regel is dezelfde redenering omgekeerd, met de ~ op vorige:

naarEen = huidige & ~vorige
bit 7 bit 6 bit 5 bit 4 bit 3 bit 2 bit 1 bit 0
vorige 00110101
huidige 00011100
~vorige 11001010
naarEen 00001000

Daar blijft enkel bit 3 over. De bits die in beide bytes gelijk zijn, bit 7, 6, 4, 2 en 1, staan in geen van beide resultaten.

Vergeet daarna niet de huidige waarde op te slaan voor de volgende vergelijking:

vorige = huidige;

Lees de code hieronder en bepaal welke bits er hoog komen te staan in naarNul:

byte vorige = B00001111;
byte huidige = B00000011;

byte naarNul = ~huidige & vorige;
Welke bits staan hoog in naarNul?

~huidige is B11111100. Een AND met vorige (B00001111) geeft B00001100, dus bit 2 en bit 3 zijn van 1 naar 0 gegaan. Bit 0 en bit 1 stonden hoog en staan nog altijd hoog, dus die zijn niet veranderd.

Een masker berekenen met <<

Alles hierboven werkt met maskers die je zelf uitschrijft, en zolang je bij het schrijven van je code al weet over welke bit het gaat, volstaat dat. Deze sectie gaat over het geval waarin je dat pas weet terwijl je programma draait. In labo 4 en labo 7 kom je die situatie tegen.

Stel dat je wil tellen hoeveel bits er in een byte hoog staan. Met de maskers die je zelf uitschrijft, wordt dat acht keer bijna dezelfde code:

byte waarde = B10110100;
byte aantalHoog = 0;

if (waarde & B00000001)
{
    aantalHoog++;
}

if (waarde & B00000010)
{
    aantalHoog++;
}

if (waarde & B00000100)
{
    aantalHoog++;
}

// en zo verder, tot B10000000

Alleen het masker verschilt tussen die blokken, dus hier hoort een lus. Met een uitgeschreven masker lukt dat niet. Zo'n masker typ je zelf in je code en het ligt dus vast voor je programma start, terwijl de teller van een lus pas tijdens het uitvoeren een waarde krijgt. Om alle acht de bits met dezelfde regel te behandelen, bereken je het masker uit het bitnummer.

Daarvoor dient <<. Je vertrekt van een 1 helemaal rechts en schuift ze een aantal plaatsen naar links. Rechts komen nullen bij:

De acht maskers, berekend met <<
Uitdrukking Binair Decimaal
1 << 0B000000011
1 << 1B000000102
1 << 2B000001004
1 << 3B000010008
1 << 4B0001000016
1 << 5B0010000032
1 << 6B0100000064
1 << 7B10000000128

De rechtse kolom is de rij plaatswaarden uit de tabel bovenaan deze pagina, want elke plaats die je opschuift verdubbelt de waarde. 1 << n is dus tegelijk het masker van bit n en de plaatswaarde van bit n. Het verschil met een uitgeschreven masker is dat n hier een variabele mag zijn.

Daarmee worden de acht blokken van hierboven één lus. Hieronder staan de twee tussenstappen in een aparte variabele, zodat je kan volgen wat er bij elke doorloop gebeurt:

byte waarde = B10110100;
byte aantalHoog = 0;

for (byte i = 0; i < 8; i++)
{
    // bij i = 0 wordt dit B00000001, bij i = 1 wordt het B00000010, bij i = 2 B00000100
    byte masker = 1 << i;

    // houdt enkel bit i van waarde over, en is 0 zodra die bit laag staat
    byte resultaat = waarde & masker;

    if (resultaat != 0)
    {
        aantalHoog++;
    }
}

// aantalHoog is nu 4

De lus loopt acht keer. Bij elke doorloop schuift het masker één plaats op, en resultaat zegt of die ene bit van waarde hoog stond:

De acht doorlopen voor waarde = B10110100
i waarde masker resultaat resultaat als getal aantalHoog
0B10110100B00000001B0000000000
1B10110100B00000010B0000000000
2B10110100B00000100B0000010041
3B10110100B00001000B0000000001
4B10110100B00010000B00010000162
5B10110100B00100000B00100000323
6B10110100B01000000B0000000003
7B10110100B10000000B100000001284
Waarom staat er 1 << i en niet i << 1 ?

Omdat het altijd dezelfde ene bit is die verschuift, en het bitnummer zegt hoe ver. i << 1 doet het omgekeerde: dat schuift de waarde van i zelf één plaats op, wat neerkomt op een verdubbeling. Bij i gelijk aan 3 levert dat 6, oftewel B00000110, en dat is helemaal geen masker: er staan twee bits hoog.

Pas de lus aan zodat ze de lage bits telt

Draai de test om: if (resultaat == 0). De rest van de lus blijft gelijk. In de tabel hierboven zijn dat de rijen waar resultaat op nul uitkomt, en dat zijn er ook 4. Zet je beide tussenstappen in de if zelf, dan heb je haakjes nodig rond de maskering: if ((waarde & (1 << i)) == 0).

Een bit zetten of wissen met een variabel bitnummer

Hetzelfde geldt voor het aanpassen van een bit. De twee vuistregels blijven gelden, alleen wordt het masker nu berekend in plaats van uitgeschreven:

byte bitNummer = 3;

patroon = patroon | (1 << bitNummer);  // die bit op 1 zetten
patroon = patroon & ~(1 << bitNummer); // die bit op 0 zetten

De tweede regel lees je van binnen naar buiten. 1 << bitNummer is B00001000 voor bitnummer 3, en ~ keert dat om tot B11110111. Dat is precies het masker dat je in de sectie hierboven zelf uitschreef. Met de verkorte schrijfwijze wordt dat patroon |= (1 << bitNummer); en patroon &= ~(1 << bitNummer);, en dat is de vorm die je in de oefeningen van labo 4 en labo 7 ziet staan.
