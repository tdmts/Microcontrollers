De spelregels van C++

De compiler leest je sketch letterlijk. Eén hoofdletter verkeerd of één puntkomma te weinig en je programma compileert niet. Hieronder staan de vormregels waar C++ op staat, telkens aangewezen op de blink-sketch die je al hebt geüpload.

Dit is de sketch waar de hele pagina naar verwijst. Hij zet de ingebouwde led op pin 13 elke seconde aan en uit.

void setup()
{
  pinMode(13, OUTPUT);      // pin 13 wordt een uitgang
}

void loop()
{
  digitalWrite(13, HIGH);   // led aan
  delay(1000);              // een seconde wachten
  digitalWrite(13, LOW);    // led uit
  delay(1000);              // een seconde wachten
}

Wat setup() en loop() precies doen, staat op Setup en loop. Deze pagina gaat over de vorm van de code, niet over wat ze uitvoert.

De puntkomma

Elke instructie eindigt op een puntkomma. Voor de compiler is dat het teken dat de instructie af is. In de sketch hierboven staat er dus een achter pinMode(13, OUTPUT);, achter elke digitalWrite(...) en achter elke delay(1000);.

Achter een accolade komt er geen puntkomma. void setup() met het blok eronder is een functiedefinitie en geen instructie, dus daar sluit de sluitende accolade het geheel af.

Vergeet je een puntkomma, dan leest de compiler jouw regel en de volgende als één instructie. De fout die hij meldt, staat daarom vaak op de regel onder de regel waar je de puntkomma vergeten bent.

Een puntkomma achter if of while

Een puntkomma op zichzelf is een geldige instructie: een lege. Zet je er een achter de voorwaarde van een if, dan is dat de volledige instructie die de if uitvoert. Het blok eronder staat er dan los van en wordt altijd uitgevoerd.

if (aantal == 5);
{
  digitalWrite(13, HIGH);   // gebeurt ook als aantal 3 is
}

Bij een while wordt die lege instructie de lus zelf. Is de voorwaarde waar, dan herhaalt je Arduino eindeloos niets en blijft je programma op die ene regel hangen.

while (aantal < 5);
{
  aantal++;                 // wordt nooit bereikt, aantal blijft staan
}

In beide gevallen is de vorm van je code correct, dus de compiler geeft je geen foutmelding. Je merkt het pas aan wat je programma doet. Zet in File > Preferences de Compiler warnings op All, dan waarschuwt hij je hier wel voor.

Wat if en while zelf doen, lees je in Selecties en Iteraties.

De accolades

Een paar accolades { } bundelt instructies tot één blok. In de blink-sketch staan twee blokken: het blok van setup() met één instructie erin, en het blok van loop() met vier.

Elke openende accolade hoort bij precies één sluitende. Vergeet je er een, dan loopt de compiler verder tot het einde van het bestand voor hij merkt dat er iets mist, en meldt hij de fout dus ergens veel verder dan waar ze staat.

In dit vak zet je de openende accolade op een eigen regel, recht onder de regel waar het blok bij hoort. Zo staat ze in dezelfde kolom als de sluitende accolade die erbij hoort, en zie je in één oogopslag welke twee bij elkaar horen.

Hoofdletters tellen mee

C++ maakt verschil tussen hoofdletters en kleine letters. digitalWrite en digitalwrite zijn voor de compiler twee verschillende namen, en alleen de eerste bestaat. Schrijf je de tweede, dan meldt de compiler dat hij die naam nergens kent.

Hetzelfde geldt voor de waarden die je meegeeft. OUTPUT, INPUT, HIGH en LOW staan volledig in hoofdletters.

En het geldt voor de namen die je zelf verzint. Noem je bovenaan iets ledPin en schrijf je verderop ledpin, dan zoekt de compiler naar een naam die je nooit gemaakt hebt.

Namen die je zelf kiest

Voor de namen van je eigen variabelen, constanten en functies gelden een paar regels:

  • Een naam bestaat uit letters, cijfers en het liggende streepje _.
  • Een naam begint met een letter, nooit met een cijfer. pin2 mag, 2pin mag niet.
  • Er staan geen spaties in. pin led leest de compiler als twee losse namen.
  • Woorden die de taal zelf gebruikt, zijn bezet. int, void, if en for kan je niet als naam kiezen.

Daarnaast is er de afspraak van dit vak: je schrijft namen in camelCase, met een kleine letter vooraan en een hoofdletter bij elk volgend woord. Zo wordt de pin van een led ledPin en niet ledpin of led_pin.

Waar je code staat

Instructies staan altijd binnen een functie. Een digitalWrite(13, HIGH); die los boven setup() zou staan, hoort bij niets en wordt door de compiler geweigerd.

Boven setup(), buiten elk blok, staat wat het hele programma nodig heeft: de #include-regels waarmee je een bibliotheek binnenhaalt, en de constanten en variabelen die meer dan één functie gebruikt. Wat je binnen een blok maakt, bestaat alleen daar. Dat verschil staat uitgewerkt in Constanten, variabelen en gegevenstypes.

Eén = is toekennen, twee is vergelijken

Met één isgelijkteken zet je een waarde in een variabele. aantal = 5; maakt van aantal een vijf.

Met twee isgelijktekens stel je een vraag. aantal == 5 verandert niets en levert true of false op, naargelang er een vijf in zit.

De verwarring tussen die twee is de klassieke beginnersfout, en de compiler ziet ze meestal niet: aantal = 5 is op zich geldige code, ze doet alleen iets anders dan je bedoelde. Je komt == voor het eerst echt tegen bij Selecties.

Commentaar

Alles achter // slaat de compiler over, tot het einde van die regel. Dat is wat er in de blink-sketch achter // led aan gebeurt: de tekst is er voor jou, de Arduino ziet ze nooit.

Voor commentaar over meerdere regels gebruik je /* om te openen en */ om te sluiten:

/*
  Blink
  Labo 0, eerste sketch
*/
digitalWrite(13, HIGH);   // led aan

De skeletcode op Setup en loop bestaat volledig uit zulke commentaarregels. Er staat dus geen enkele instructie in, en toch compileert ze.

Inspringen en witruimte

Spaties, tabs en lege regels tellen niet mee voor de compiler. De hele blink-sketch op één lange regel zetten levert exact hetzelfde programma op. Voor wie de code leest, maakt het wel uit, en dat ben jij zelf zodra je sketch langer wordt dan een scherm.

De afspraak is: één instructie per regel, en per blok spring je een niveau in. Alles wat tussen de accolades van loop() staat, staat dus even ver van de kantlijn.

De IDE springt zelf in

Met Ctrl+T (of Tools > Auto Format) laat je de Arduino IDE je hele sketch opnieuw uitlijnen. Loopt de inspringing daarna vreemd, dan is dat meestal het spoor van een accolade die je vergeten bent.
