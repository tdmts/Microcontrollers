Vragen

Vraag 1: welke leds branden? (meerkeuze)

Op een 74HC595 hangen acht leds: led 1 op Q0 tot en met led 8 op Q7. Je laadt er dit patroon in.

const int pinDS = 2;
const int pinSTCP = 3;
const int pinSHCP = 4;

const bool patroon[8] = {1, 1, 0, 0, 0, 0, 0, 0};

void risingEdge(int pinNummer)
{
  digitalWrite(pinNummer, LOW);
  digitalWrite(pinNummer, HIGH);
}

void setup()
{
  pinMode(pinDS, OUTPUT);
  pinMode(pinSTCP, OUTPUT);
  pinMode(pinSHCP, OUTPUT);
}

void loop()
{
  for (int i = 0; i < 8; i++)
  {
    if (patroon[i] == 1)
    {
      digitalWrite(pinDS, HIGH);
    }
    else
    {
      digitalWrite(pinDS, LOW);
    }

    risingEdge(pinSHCP);
  }

  risingEdge(pinSTCP);
}

Welke uitgangen staan er hoog?

  1. Q0 en Q1
  2. Q6 en Q7
  3. Alle acht, want de bits blijven doorschuiven
  4. Geen enkele, want STCP staat buiten de lus

Antwoord: b) Q6 en Q7

De bit die je er als laatste inschuift, komt op Q0 terecht. De eerste bit die je inschuift, is dus ook diegene die het verst doorschuift, helemaal tot Q7. Deze lus begint bij patroon[0], en die belandt daarom op Q7. patroon[1] komt op Q6, en de zes nullen die daarna volgen vullen Q5 tot Q0 op.

Wil je dat de twee enen op Q0 en Q1 uitkomen, dan moet je de array in de omgekeerde volgorde doorlopen. Dat is precies waarom de oplossingen in labo 3 aftellen van led 8 naar led 1 in plaats van op te tellen.

Antwoord d) is een strikvraag: risingEdge(pinSTCP) hoort net wel buiten de lus. Zolang je enkel op SHCP klokt, verandert er niets aan de uitgangen. Die ene flank op STCP op het einde kopieert het schuifregister in één keer naar het storage register, en pas dan wordt alles tegelijk zichtbaar.

Vraag 2: de I²C-bus en de PCF8574 (meerdere juiste antwoorden)

Welke van onderstaande uitspraken zijn juist? Er zijn er meerdere juist.

  1. Op een Arduino UNO liggen SDA en SCL vast op A4 en A5.
  2. Je kan acht PCF8574's met hetzelfde basisadres op dezelfde bus hangen door A0, A1 en A2 telkens anders te bedraden.
  3. Een pin van de PCF8574 die je als ingang wil gebruiken, zet je eerst laag door er een 0 naar te schrijven.
  4. Hang je maar één chip aan de bus, dan mag je A0, A1 en A2 gerust laten zweven.
  5. De /INT-pin meldt dat er iets veranderd is op de I/O-lijnen, zodat je daar niet constant naar hoeft te vragen.

Antwoord: a, b en e zijn juist. c en d zijn fout.

  • a) juist. Dat is geen keuze die je zelf maakt: de I²C-hardware in de chip hangt nu eenmaal aan die twee pinnen. Op een UNO R3 zijn dezelfde twee lijnen ook nog eens apart uitgebracht naast de AREF-pin, dus daar aansluiten mag ook. Op een Leonardo zijn het pinnen 2 en 3.
  • b) juist. A2, A1 en A0 zijn verbonden met de laagste drie bits van het adres. Met drie lijnen maak je acht combinaties, dus acht adressen vanaf hetzelfde basisadres. Bij basisadres 0x38 gaat dat van 0x38 tot 0x3F, goed voor 64 extra I/O-lijnen op twee Arduinopinnen.
  • c) fout. Net omgekeerd. De pinnen zijn quasi-bidirectioneel: er is geen aparte in- of uitgangsinstelling. Een pin die je wil lezen moet een 1 in zijn uitgangslatch hebben. Schreef je er eerder een 0 naar, dan lees je die 0 gewoon terug en lijkt je knop permanent ingedrukt.
  • d) fout. A0, A1 en A2 moeten altijd aan GND of aan Vcc hangen, ook bij één chip. Laat je ze zweven, dan ligt het adres niet vast en vind je de chip soms wel en soms niet terug met de I2C scanner.
  • e) juist. Dat is precies waar /INT voor dient. In labo 4 gebruik je die functie nog niet en vraag je de knoppen elke doorloop zelf op, maar in labo 7 hang je hem aan een interruptpin.

Vraag 3: twee schuifregisters in cascade (open vraag)

Je wil zestien leds aansturen met twee 74HC595's, en je wil daarvoor nog altijd maar drie pinnen van je Arduino gebruiken.

  1. Leg uit hoe je die twee chips met elkaar verbindt, en wat er met de bits gebeurt terwijl je ze inschuift.
  2. Je schuift eerst de acht bits voor het ene register in en dan die voor het andere. Waarom geef je pas op het einde één flank op STCP, en niet na elke acht bits?

Deel 1

SHCP en STCP van beide chips hang je gewoon parallel: ze krijgen allebei dezelfde klok en dezelfde latchflank, dus ze werken volledig in de pas. Enkel de dataweg is een ketting. DS van het eerste register komt van je Arduino, en Q7S van het eerste register gaat naar DS van het tweede. Q7S is de seriële uitgang: daar verlaat een bit het register wanneer hij er aan de andere kant uitgeduwd wordt.

Schuif je nu zestien bits in, dan blijven de laatste acht in het eerste register staan, en zijn de eerste acht er langs Q7S uitgeschoven en in het tweede terechtgekomen. Wat je eerst inschuift, schuift dus door naar het tweede register. Dat is dezelfde regel als bij één chip, alleen loopt de rij nu over zestien plaatsen in plaats van acht.

Deel 2

Omdat het schuifregister en het storage register los van elkaar staan. Zolang je enkel op SHCP klokt, verandert er niets aan de uitgangen: je bent achter de schermen aan het opbouwen wat er straks moet komen te staan. Pas bij een stijgende flank op STCP springt alles tegelijk zichtbaar op de uitgang.

Latch je na de eerste acht bits, dan maak je een tussenstand zichtbaar waarin het eerste register al de nieuwe waarde toont terwijl het tweede nog de oude heeft, of erger nog, waarin de eerste byte kort op de verkeerde chip staat te branden voor hij doorgeschoven is. Bij een teller op twee displays zie je dat als flikkeren en als cijfers die niet gelijk omspringen. Eén flank op het einde laat alle zestien uitgangen op hetzelfde moment veranderen.

Vraag 4: bits aanpassen (numeriek)

Op de acht pinnen van een PCF8574 hangen acht leds. Op dit moment staat er in je programma:

byte poort = B11010110;

Bereken:

  1. Diezelfde waarde in hexadecimale en in decimale notatie.
  2. De led op P2 moet uit, de zeven andere blijven zoals ze zijn. Geef de expressie en de nieuwe waarde van poort, binair.
  3. Daarna moet de led op P5 er nog bij aan. Geef opnieuw de expressie en de nieuwe waarde, en leg uit waarom je dat niet doet met poort = B00100000;.

1. 0xD6 en 214

Voor hexadecimaal splits je de byte in twee groepjes van vier bits: 1101 is D en 0110 is 6, samen 0xD6. Decimaal tel je de plaatswaarden van de enen op: 128 + 64 + 16 + 4 + 2 = 214.

2. poort &= ~(1 << 2); geeft B11010010

Lees die expressie van binnen naar buiten. 1 << 2 is B00000100, het masker van bit 2. De ~ keert dat om tot B11111011: overal een 1, behalve op de plaats van bit 2. Een AND daarmee laat elke andere bit gewoon zichzelf blijven en maakt enkel bit 2 gegarandeerd 0.

B11010110 & B11111011
P7 P6 P5 P4 P3 P2 P1 P0
poort 11010110
masker 11111011
resultaat 11010010

3. poort |= (1 << 5); geeft B11110010

Met OR zet je een bit op 1 zonder de rest te raken: overal waar het masker 0 staat blijft de bit die er al stond. B11010010 met B00100000 erbij geeft B11110010, oftewel 0xF2 of 242.

Waarom niet poort = B00100000;? Omdat je bij een PCF8574 altijd de hele byte naar de chip schrijft. Je kan geen enkele pin apart aanspreken. Zet je poort zomaar gelijk aan B00100000, dan zeg je in één keer dat P5 aan moet en alle zeven andere uit. De leds op P7, P6 en P1 zouden dus doven, terwijl je die niet gevraagd hebt te veranderen.

Vraag 5: zoek de twee fouten (code)

Een student bouwt een looplicht dat één plaats opschuift telkens je op de knop drukt. De acht leds hangen aan een 74HC595, de knop hangt aan P0 van een PCF8574. De schakeling is correct gebouwd en de I2C scanner vindt de chip op 0x38.

Toch klopt er niets van. Bij het opstarten schuift het licht één keer op, en daarna verandert de knop niets meer. En in plaats van één heldere led branden er verschillende leds flauw.

#include <Wire.h>

const int adresExpander = 0x38;

const int pinDS = 2;
const int pinSTCP = 3;
const int pinSHCP = 4;

byte patroon = B00000001;
byte vorigeKnoppen = 0xFF;

void risingEdge(int pinNummer)
{
  digitalWrite(pinNummer, LOW);
  digitalWrite(pinNummer, HIGH);
}

void setup()
{
  pinMode(pinDS, OUTPUT);
  pinMode(pinSTCP, OUTPUT);
  pinMode(pinSHCP, OUTPUT);

  Wire.begin();

  Wire.beginTransmission(adresExpander);
  Wire.write(B00000000);
  Wire.endTransmission();
}

void loop()
{
  byte knoppen = 0xFF;

  Wire.requestFrom(adresExpander, 1);

  if (Wire.available())
  {
    knoppen = Wire.read();
  }

  byte netIngedrukt = ~knoppen & vorigeKnoppen;
  vorigeKnoppen = knoppen;

  if (netIngedrukt & B00000001)
  {
    patroon = patroon << 1;

    if (patroon == 0)
    {
      patroon = B00000001;
    }
  }

  for (int led = 8; led >= 1; led--)
  {
    if (patroon & (1 << (led - 1)))
    {
      digitalWrite(pinDS, HIGH);
    }
    else
    {
      digitalWrite(pinDS, LOW);
    }

    risingEdge(pinSHCP);
    risingEdge(pinSTCP);
  }
}

Er zitten twee fouten in. Welke, en hoe los je ze op?

Fout 1: de setup schrijft een 0 naar de knoppin

In de setup() gaat er B00000000 naar de expander, en dus ook een 0 naar P0. De pinnen van de PCF8574 zijn quasi-bidirectioneel: een pin die je wil lezen moet een 1 in zijn uitgangslatch hebben. Met een 0 erin lees je die 0 gewoon terug, wat je programma leest als een permanent ingedrukte knop.

Dat verklaart ook precies wat de student ziet. vorigeKnoppen start op 0xFF, dus de allereerste doorloop denkt dat de knop net ingedrukt werd en schuift één keer op. Daarna staat vorigeKnoppen ook op 0 en gaat er nooit nog een bit van 1 naar 0. De knop is dood.

Oplossing: zet de pinnen die je als ingang gebruikt hoog.

Wire.write(B11111111);

Fout 2: er wordt gelatcht na elke bit

risingEdge(pinSTCP) staat binnen de lus, dus na elke ingeschoven bit wordt het schuifregister naar het storage register gekopieerd. Elke tussenstand komt zo op de uitgangen terecht: acht zichtbare patronen in plaats van één. Omdat dat sneller gaat dan je oog kan volgen, zie je geen looplicht maar een aantal flauw brandende leds.

Oplossing: schuif eerst alle acht de bits in, en latch pas daarna één keer.

for (int led = 8; led >= 1; led--)
{
  if (patroon & (1 << (led - 1)))
  {
    digitalWrite(pinDS, HIGH);
  }
  else
  {
    digitalWrite(pinDS, LOW);
  }

  risingEdge(pinSHCP);
}

risingEdge(pinSTCP);
