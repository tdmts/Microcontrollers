Van pollen naar interrupts

Tot nu toe las je je knoppen uit door er in je loop() naar te kijken. Dat werkt goed zolang je programma verder niets te doen heeft. Zodra er ook iets anders moet gebeuren, mis je drukken, en een interrupt is wat dat oplost.

Pollen: telkens opnieuw gaan kijken

Een knop uitlezen doe je met digitalRead(). Die functie vertelt je hoe de pin er op dat ene moment bij ligt. Wil je weten of er ondertussen op de knop gedrukt is, dan moet je dus blijven kijken, ronde na ronde.

Die manier van werken heet pollen. Je vraagt herhaaldelijk "en nu? en nu? en nu?".

const int knopPin = 2;
const int ledPin = 8;

void setup()
{
  pinMode(knopPin, INPUT_PULLUP);
  pinMode(ledPin, OUTPUT);
}

void loop()
{
  if (digitalRead(knopPin) == LOW) // ingedrukt
  {
    digitalWrite(ledPin, HIGH);
  }
}

Deze loop() draait duizenden keren per seconde. Je kan de knop onmogelijk zo kort indrukken dat hij hem mist. Zolang dit het enige is wat je programma doet, is pollen in orde.

Waar het misgaat

Nu zet je er één regel bij.

const int knopPin = 2;
const int ledPin = 8;

void setup()
{
  pinMode(knopPin, INPUT_PULLUP);
  pinMode(ledPin, OUTPUT);
}

void loop()
{
  if (digitalRead(knopPin) == LOW)
  {
    digitalWrite(ledPin, HIGH);
  }

  delay(1000); // hier gebeurt iets anders, wat dan ook
}

Vanaf nu wordt je knop nog maar één keer per seconde bekeken. Druk je de knop in en laat je hem los terwijl die delay() loopt, dan heeft je programma er nooit iets van gemerkt. De druk is weg.

Een kortere delay() lost dat niet op. Elke seconde die je programma ergens anders mee bezig is, is een seconde waarin het je knop niet bekijkt.

Een noodstop die tien seconden te laat komt

Kijk eens naar dit programma. Twee leds wisselen elkaar af, met tien seconden ertussen. Op pin 2 zit een noodstop. Druk je die in, dan moeten alle leds doven en blijven ze uit.

const int knopPin = 2;
const int ledPin1 = 3;
const int ledPin2 = 4;

bool noodstop = false;
int teller = 0;

void setup()
{
  pinMode(knopPin, INPUT_PULLUP);
  pinMode(ledPin1, OUTPUT);
  pinMode(ledPin2, OUTPUT);
}

void loop()
{
  if (digitalRead(knopPin) == LOW) // noodstop ingedrukt
  {
    noodstop = true;
  }

  if (noodstop == true)
  {
    digitalWrite(ledPin1, LOW);
    digitalWrite(ledPin2, LOW);
  }
  else
  {
    if (teller % 2 == 0)
    {
      digitalWrite(ledPin1, HIGH);
      digitalWrite(ledPin2, LOW);
    }
    else
    {
      digitalWrite(ledPin1, LOW);
      digitalWrite(ledPin2, HIGH);
    }

    delay(10000);
    teller++;
  }
}
Hoe lang moet je die noodstop ingedrukt houden voor de leds doven?

Denk er even over na voor je verder leest. Het antwoord is niet "een fractie van een seconde".

De loop() zit in delay(10000). Pas als die tien seconden om zijn, kijkt het programma weer naar de knop. Laat je de noodstop vóór dat moment los, dan is er niets gebeurd. Je moet hem dus in het slechtste geval tien seconden lang ingedrukt houden.

Zo'n noodstop is onbruikbaar.

Wat een interrupt daaraan verandert

Je code is correct, maar het probleem is dat je programma zelf moet gaan kijken. Zolang het ergens anders mee bezig is, kan het dat niet.

Een interrupt draait dat om. Je vraagt niet meer of er iets gebeurd is, maar je wordt geroepen wanneer het gebeurt.

In de chip zit hardware die een paar pinnen in de gaten houdt, helemaal los van je programma. Ziet die hardware op zo'n pin de spanning veranderen, dan onthoudt ze dat meteen, en zodra de lopende instructie klaar is wordt je programma onderbroken. Het wordt middenin gepauzeerd en niet eerst afgewerkt.

De controller springt dan naar een functie die jij geschreven hebt. Die functie heet de interrupt service routine, kortweg de ISR. Zodra ze klaar is, gaat je programma verder waar het gebleven was, alsof er niets gebeurd is. Zat je in een delay(), dan telt die gewoon verder af.

Een interrupt houdt de flank vast in hardware

Bij pollen kan je een korte druk missen omdat je op het verkeerde moment keek. Bij een interrupt is dat onmogelijk, want de flank wordt in hardware vastgehouden, ook als je programma net iets anders aan het doen was. Zelfs een druk van een duizendste van een seconde raakt niet verloren.

Hetzelfde noodstopprogramma, nu met een interrupt. Er veranderen maar twee dingen, en ze zijn allebei gemarkeerd:

const int knopPin = 2;
const int ledPin1 = 3;
const int ledPin2 = 4;

volatile bool noodstop = false; // 1: volatile, want de ISR verandert dit
int teller = 0;

// De interrupt service routine. Kort, en meer niet.
void noodstopIngedrukt()
{
  digitalWrite(ledPin1, LOW);
  digitalWrite(ledPin2, LOW);

  noodstop = true;
}

void setup()
{
  pinMode(ledPin1, OUTPUT);
  pinMode(ledPin2, OUTPUT);
  pinMode(knopPin, INPUT_PULLUP);

  // 2: koppel de functie aan de pin
  attachInterrupt(digitalPinToInterrupt(knopPin), noodstopIngedrukt, FALLING);
}

void loop()
{
  if (noodstop == true)
  {
    digitalWrite(ledPin1, LOW);
    digitalWrite(ledPin2, LOW);
  }
  else
  {
    if (teller % 2 == 0)
    {
      digitalWrite(ledPin1, HIGH);
      digitalWrite(ledPin2, LOW);
    }
    else
    {
      digitalWrite(ledPin1, LOW);
      digitalWrite(ledPin2, HIGH);
    }

    delay(10000);
    teller++;
  }
}

Merk op dat de loop() nu niet meer naar de knop kijkt. Die regel is verdwenen. En toch doven de leds op het moment dat je drukt, ook al zit de loop() nog acht seconden vast in zijn delay().

Het belangrijkste idee van dit labo

Kijk goed naar wat er in die ISR staat, en vooral naar wat er niet in staat.

De ISR doet het dringende werk aan de hardware en zet de leds uit. Dat moet nu gebeuren, en het duurt maar een paar microseconden. Daarnaast zet ze een vlag: noodstop = true. Die vlag is er voor de loop(), zodat die weet dat hij de leds niet opnieuw mag aansteken zodra zijn delay() afgelopen is.

Onthou deze ene zin

De ISR doet het dringende werk, de vlag doet het beleid.

Alles wat echt niet kan wachten en in een oogwenk klaar is, zet je in de ISR. Alles wat mag wachten tot je loop() weer aan de beurt is, laat je aan de loop() over. Bijna elke fout die je dit labo maakt, komt erop neer dat je te veel in de ISR gestopt hebt.

Verder lezen

  • volatile en de vlagvariabele voor het woord volatile en het vlagpatroon.
