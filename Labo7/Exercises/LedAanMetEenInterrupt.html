Een led die aangaat zonder loop

Je eerste interrupt, en meteen het bewijs dat hij werkt: je loop() blijft helemaal leeg, en toch reageert je led op de knop.

Zes labo's lang stond alles wat er moest gebeuren in je loop(). Deze keer laat je die met opzet leeg. Werkt je programma toch, dan weet je zeker dat de interrupt het werk gedaan heeft, want er is niets anders dat het gedaan kán hebben.

Deze oefening werk je uit in TinkerCAD.

Wat je nodig hebt

De aansluitingen
Pin Waarop
pin 2 Een drukknop naar de massa, met INPUT_PULLUP
pin 8 Een led, via een weerstand van 220 Ω naar de massa
De knop móét op pin 2 of pin 3

Op een Arduino UNO kunnen maar twee pinnen een interrupt opwekken. Zet je je knop ergens anders, dan compileert alles netjes en gebeurt er nooit iets. Zie attachInterrupt en de interruptpinnen.

Wat je moet programmeren

  1. Schrijf een functie die de led aanzet. Ze is void en heeft geen parameters.
  2. Koppel die functie in je setup() aan pin 2 met attachInterrupt(), en laat hem afgaan op de dalende flank.
  3. Laat je loop() volledig leeg. Er mag geen enkele regel in staan.

Denk aan de volgorde in je setup(): eerst pinMode(), dan pas attachInterrupt().

Wat je zal zien

Bij het opstarten gebeurt er niets. Druk je op de knop, dan gaat de led aan. En dan blijft hij aan.

Dat is geen fout, dat is precies wat je geschreven hebt: er staat nergens iets dat de led weer uitzet. Druk je nog eens, dan gaat je ISR opnieuw af, maar je ziet er niets van omdat de led al brandt. Wil je opnieuw beginnen, druk dan op de resetknop van je Arduino.

Probeer dit eens, het is de hele les van deze oefening

Zet als proef een delay(5000) in je loop(). Je programma zit nu vijf seconden per keer niets te doen.

Druk nu op de knop. De led gaat nog altijd meteen aan, ook al zit je loop() midden in die vijf seconden vast. Precies dat kon je met digitalRead() nooit voor elkaar krijgen.

Haal die delay() daarna weer weg voor je indient.

Oplossing

Merk op hoe weinig code dit is. De hele werking zit in die ene regel attachInterrupt().

const int knopPin = 2;  // enkel pin 2 en pin 3 kunnen dit op een UNO
const int ledPin = 8;

// De interrupt service routine. Altijd void, altijd zonder parameters.
void ledAan()
{
  digitalWrite(ledPin, HIGH);
}

void setup()
{
  pinMode(ledPin, OUTPUT);
  digitalWrite(ledPin, LOW);

  // Eerst de pin instellen, pas daarna de interrupt aanzetten. Doe je het
  // omgekeerd, dan maak je met het inschakelen van de pull-up zelf een
  // flank op die pin, en gaat je ISR meteen bij het opstarten al af.
  pinMode(knopPin, INPUT_PULLUP);

  attachInterrupt(digitalPinToInterrupt(knopPin), ledAan, FALLING);
}

void loop()
{
  // Met opzet leeg. Al het werk gebeurt in de ISR.
}
Waarom FALLING en niet RISING?

Met INPUT_PULLUP staat de pin hoog zolang je niets doet. Druk je, dan verbindt de knop hem met de massa en gaat hij naar laag. De flank op het moment van indrukken is dus een dálende flank.

Schrijf je RISING, dan gaat je led pas branden op het moment dat je de knop weer loslaat. Probeer het gerust eens, het maakt het verschil meteen duidelijk.

Er staan geen haakjes achter ledAan

In attachInterrupt(digitalPinToInterrupt(knopPin), ledAan, FALLING) staat ledAan zonder haakjes. Je roept de functie hier niet op: je geeft door welke functie er later opgeroepen moet worden.

Schrijf je ledAan() met haakjes, dan probeert de compiler het resultaat van de functie door te geven. Die geeft niets terug, dus krijg je een foutmelding. Dat is er dan nog eentje die je zelf kan oplossen.
