Drukken tellen zonder dender

Je led moet nu omschakelen bij elke druk, en je wil weten hoeveel keer er gedrukt is. Daarbij kom je twee valkuilen tegen die in de rest van dit labo terugkomen.

Vertrek van je vorige oefening. Dezelfde bedrading, alleen de code verandert.

Wat je nodig hebt

De aansluitingen
Pin Waarop
pin 2 De drukknop, met INPUT_PULLUP
pin 8 De led, via een weerstand van 220 Ω

Wat je moet programmeren

  1. Elke druk op de knop schakelt de led om: brandt hij, dan gaat hij uit, en omgekeerd.
  2. Je houdt bij hoeveel keer er gedrukt is.
  3. Je loop() print dat aantal naar de seriële monitor, maar alleen wanneer het veranderd is.
Het printen hoort in je loop()

Het is verleidelijk om die Serial.println() in je ISR te zetten, want daar weet je toch dat er gedrukt is. Doe het niet. Printen duurt bij 9600 baud makkelijk tientallen milliseconden, en zolang je ISR bezig is staat je hele controller stil.

De teller ophogen doe je in de ISR, het printen in je loop(). Zie De regels van een ISR.

Probeer eerst de simpele versie

Schrijf je programma eerst zonder je zorgen te maken over de details. Je ISR schakelt de led om en telt op, je loop() print. Upload het, en druk vijf keer.

Werk je op een echt bord, dan zie je waarschijnlijk iets als 3, 9, 14, 21. Werk je in TinkerCAD, dan zie je 1, 2, 3, 4, 5.

Een echte knop stuitert bij elke druk

De drukknop in TinkerCAD maakt precies één keer contact. Een echte knop is een stuk veerend metaal en stuitert bij het indrukken vijf tot twintig keer heen en weer. Elk van die stuiteringen is een dalende flank, en je interrupt mist er geen enkele.

Je moet die ontdendering dus schrijven, ook al zie je in de simulator het probleem niet. Anders ontdek je op het labo dat je teller nergens op slaat. Lees Denderen bij een interrupt.

De twee dingen die je moet oplossen

  1. De dendering. Onthou in je ISR wanneer je de vorige druk aanvaard hebt, en negeer alles wat binnen de 200 ms daarna nog binnenkomt.
  2. Het lezen van je teller. Je teller is een unsigned long, dus vier bytes. Je loop() kan die niet in één keer ophalen, en je ISR kan er middenin springen. Maak een kopie tussen noInterrupts() en interrupts(). Waarom dat nodig is, staat in volatile en de vlagvariabele.

Vergeet niet dat alles wat je ISR aanraakt volatile moet zijn.

Oplossing

Twee dingen om op te letten. In de ISR staat een return die er meteen weer uitstapt zodra blijkt dat het gestuiter is, en dat is de goedkoopste manier om een flank weg te gooien. In de loop() staan precies twee regels tussen noInterrupts() en interrupts(), niet meer.

const int knopPin = 2;
const int ledPin = 8;

const unsigned long vergrendelTijd = 200; // zolang negeren we nieuwe flanken

volatile bool ledBrandt = false;
volatile unsigned long aantalDrukken = 0;
volatile unsigned long laatsteDruk = 0;

unsigned long vorigAantal = 0; // hier komt alleen de loop aan

void knopIngedrukt()
{
  // millis() loopt niet verder zolang we in een ISR zitten, maar de waarde
  // die we hier lezen is die van vlak voor de onderbreking. Voor 200 ms is
  // dat nauwkeurig genoeg, en bij de volgende druk staat de klok weer verder.
  unsigned long nu = millis();

  if (nu - laatsteDruk < vergrendelTijd)
  {
    return; // dit is gestuiter, geen nieuwe druk
  }

  laatsteDruk = nu;

  ledBrandt = !ledBrandt;
  digitalWrite(ledPin, ledBrandt);

  aantalDrukken++;
}

void setup()
{
  pinMode(ledPin, OUTPUT);
  digitalWrite(ledPin, LOW);

  pinMode(knopPin, INPUT_PULLUP);

  Serial.begin(9600);

  attachInterrupt(digitalPinToInterrupt(knopPin), knopIngedrukt, FALLING);
}

void loop()
{
  // aantalDrukken is vier bytes groot. De processor haalt die stuk voor stuk
  // op, en de ISR kan daar net tussen springen. Dan lees je een getal dat
  // nooit bestaan heeft. Dus: heel even niet storen, kopie maken, klaar.
  noInterrupts();
  unsigned long aantal = aantalDrukken;
  interrupts();

  if (aantal != vorigAantal)
  {
    vorigAantal = aantal;

    Serial.print("Aantal drukken: ");
    Serial.println(aantal);
  }
}
Waarom alleen de ISR aan laatsteDruk komt

laatsteDruk is ook vier bytes groot, en toch staat er nergens een noInterrupts() omheen. Dat komt omdat alleen de ISR eraan komt, en een ISR kan zichzelf niet onderbreken, want zolang ze draait staan alle interrupts uit.

De vuistregel is dat bescherming nodig is zodra je loop() én je ISR allebei aan dezelfde variabele van meer dan één byte komen.

Als je 200 keer per seconde moet tellen

Dan werkt deze vergrendeling niet meer, want ze gooit alles binnen 200 ms weg. Bij een toerenteller of een debietmeter, waar de pulsen van een sensor komen in plaats van van een vinger, laat je de ontdendering dus weg, want elektronica stuitert niet.

Ontdenderen is er voor mechanische contacten.
