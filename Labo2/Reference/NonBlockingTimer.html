Non-blocking timer

Een delay(1000) legt je hele programma een seconde stil, dus een knopdruk in die seconde merk je nooit op. Met millis() vraag je op hoe lang je Arduino al aan staat. Met dat getal ga je zelf na of het interval voorbij is, en blijf je ondertussen je knop inlezen en je display verversen.

Waarom delay() je programma stillegt

Eén led en één knop. De led knippert elke seconde, en zolang je de knop indrukt, moet ze blijven branden.

const int ledPin = 3;
const int knopPin = 2;

void setup()
{
  pinMode(ledPin, OUTPUT);
  pinMode(knopPin, INPUT_PULLUP);
}

void loop()
{
  if (digitalRead(knopPin) == LOW)
  {
    digitalWrite(ledPin, HIGH);
  }
  else
  {
    digitalWrite(ledPin, HIGH);
    delay(1000); // een seconde lang gebeurt er niets anders
    digitalWrite(ledPin, LOW);
    delay(1000); // en hier opnieuw
  }
}

Een delay(1000) houdt je Arduino een volle seconde tegen. Hij voert in die tijd geen enkele regel code uit. De knop wordt hier dus maar één keer per twee seconden uitgelezen. Druk je kort, dan is je druk alweer voorbij tegen dat digitalRead() aan bod komt en gebeurt er niets. Hou je de knop vast, dan blijft de led nog tot twee seconden verder knipperen voor ze reageert.

Je hebt dus een manier nodig om te vragen "is er al een seconde voorbij?" zonder daarop te blijven staan wachten. Dat is wat een non-blocking timer doet: je kijkt op de klok, en als het nog geen tijd is, ga je gewoon verder met de rest van je loop().

Wat millis() teruggeeft

millis() geeft het aantal milliseconden terug sinds je Arduino is opgestart. Die teller loopt op de achtergrond mee en begint bij nul zodra je het bord van spanning voorziet of op de resetknop drukt.

Je kan er geen tijdstip mee instellen en hem ook niet terugzetten. Wat je er wel mee kan, is twee metingen van elkaar aftrekken. Het verschil tussen de tijd van nu en een tijd die je eerder bewaarde, is het aantal milliseconden dat sindsdien voorbij is.

Het patroon

Elke non-blocking timer bestaat uit dezelfde drie stukken: een variabele waarin je het tijdstip van de vorige keer bewaart, een constante met het interval, en een if die de twee vergelijkt. Hieronder staat hetzelfde programma als hierboven, nu zonder delay(). De led wisselt nog altijd elke seconde van toestand, maar loop() blijft ondertussen duizenden keren per seconde doorlopen, en de knop wordt dus even vaak uitgelezen.

const int ledPin = 3;
const int knopPin = 2;
const unsigned long interval = 1000; // 1 seconde

unsigned long vorigeMillis = 0;

void setup()
{
  pinMode(ledPin, OUTPUT);
  pinMode(knopPin, INPUT_PULLUP);
}

void loop()
{
  unsigned long nu = millis(); // hoe laat is het nu?

  if (nu - vorigeMillis >= interval) // in plaats van delay(1000)
  {
    vorigeMillis = nu; // onthoud wanneer het interval verstreek

    // Voer uit omdat het interval verstreek: wissel de led
    if (digitalRead(ledPin) == LOW)
    {
      digitalWrite(ledPin, HIGH);
    }
    else
    {
      digitalWrite(ledPin, LOW);
    }
  }

  // Voer altijd uit: lees de knop in en zet de led aan zolang ze ingedrukt is
  if (digitalRead(knopPin) == LOW)
  {
    digitalWrite(ledPin, HIGH);
  }
}

De loop() bestaat nu uit twee losse if-blokken die niets van elkaar hoeven te weten. Het eerste is de timer: is er sinds de vorige omschakeling een seconde voorbij, dan zet je vorigeMillis op de huidige tijd en wissel je de led om. Om te weten of ze aan of uit staat, lees je de uitgangspin terug, want digitalRead() geeft je op een uitgang terug wat je er als laatste naartoe schreef.

Het tweede blok is de knop, en dat is dezelfde regel als in het programma met delay(). De vergelijking van de timer is bijna altijd onwaar, en dan valt de loop() meteen door naar die knop. Zo wordt digitalRead(knopPin) duizenden keren per seconde uitgevoerd in plaats van één keer per twee seconden, en reageert de knop onmiddellijk.

Bewaar de tijd in een variabele

In het voorbeeld hierboven wordt millis() één keer per doorloop opgevraagd en in nu gezet. Je kan de functie ook overal rechtstreeks aanroepen, maar dan kan de tijd tussen twee regels van dezelfde doorloop al verschoven zijn. Met één meting per doorloop werken al je timers met exact hetzelfde tijdstip.

Waarom unsigned long

millis() geeft een unsigned long terug, en je eigen tijdvariabelen moeten dat dus ook zijn. Een unsigned long is vier bytes groot en kan tellen tot 4 294 967 295.

Zet je een tijdstip in een gewone int, dan loopt die na 32 767 over. Dat is iets meer dan 32 seconden na het opstarten, en vanaf dan klopt je timing niet meer. De fout valt op korte termijn nauwelijks op, wat het lastig maakt om ze terug te vinden.

Na 49 dagen begint millis() opnieuw

Ook een unsigned long raakt ooit vol: na ongeveer 49 dagen springt millis() terug naar nul. Zolang je het verschil berekent zoals hierboven, nu - vorigeMillis, blijft je timer daar correct doorlopen. Schrijf je de vergelijking als nu >= vorigeMillis + interval, dan gaat het op dat ene moment wel mis. Beide vormen lijken hetzelfde te doen, dus hou de eerste aan.

Eén keer wachten in plaats van herhalen

De timer hierboven herhaalt zich: hij zet vorigeMillis op de nieuwe tijd en begint meteen aan het volgende interval. Vaak wil je iets anders, namelijk één afgemeten duur die start op een moment dat jij bepaalt.

Zo'n eenmalige timer bouw je in Nachtlamp met tijd.
