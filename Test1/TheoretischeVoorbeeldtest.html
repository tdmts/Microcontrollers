Vragen

Vraag 1: wat drukt deze sketch af? (meerkeuze)

Je leest een potentiometer uit en zet de waarde om naar een spanning. Op het moment van de meting geeft analogRead() de waarde 614 terug.

const int potPin = A0;

void setup()
{
  Serial.begin(9600);
}

void loop()
{
  int waarde = analogRead(potPin);
  double spanning = waarde / 1023 * 5;
  Serial.println(spanning);
  delay(500);
}

Welke waarde verschijnt er in de seriële monitor?

  1. 3.00
  2. 0.00
  3. 614.00
  4. 2.50

Antwoord: b) 0.00

Zowel waarde als 1023 is een int, dus de Arduino maakt hier een gehele deling. 614 gedeeld door 1023 is 0 met rest, en die rest wordt weggegooid. Daarna wordt 0 nog eens maal 5 gedaan, wat 0 blijft. Dat het resultaat in een double terechtkomt, verandert daar niets aan: de deling is al gebeurd voor de toekenning.

Je lost het op door van minstens één van de twee getallen een kommagetal te maken:

double spanning = waarde / 1023.0 * 5;

Dan krijg je 614 / 1023.0 = 0,6002 en maal 5 geeft ongeveer 3,00 V, wat antwoord a) zou zijn geweest als de code juist stond.

Vraag 2: knoppen uitlezen (meerdere juiste antwoorden)

Welke van onderstaande uitspraken over het uitlezen van een drukknop zijn juist? Er zijn er meerdere juist.

  1. Een ingang zonder pull-up- of pull-downweerstand gedraagt zich als een antenne en leest willekeurig hoog of laag.
  2. Met INPUT_PULLUP en een NO-knop naar de massa lees je LOW wanneer de knop ingedrukt is.
  3. Je kan met pinMode() ook een ingebouwde pull-downweerstand inschakelen.
  4. Bij een externe pull-downweerstand moet de andere kant van de NO-knop naar +5 V.
  5. Een pull-upweerstand is typisch 220 Ω.

Antwoord: a, b en d zijn juist. c en e zijn fout.

  • a) juist. Aan een NO-knop in rust hangt er letterlijk een los stuk draad aan je ingang. Dat pikt storing uit de omgeving op, en dan zwabbert je ingang tussen hoog en laag zonder dat je iets aanraakt.
  • b) juist. De interne pull-up trekt de ingang naar +5 V zolang je niets doet, dus in rust lees je HIGH. Druk je de knop in, dan verbind je de ingang rechtstreeks met de massa en lees je LOW. Zo'n ingang noemen we laag assertief: ingedrukt is 0.
  • c) fout. De Arduino heeft alleen een ingebouwde pull-up. Wil je een pull-down, dan moet je die zelf op je breadboard zetten.
  • d) juist. De pull-down houdt de ingang in rust op 0 V. Om er een 1 op te krijgen moet de knop de ingang met +5 V verbinden. Deze ingang is dus hoog assertief, net omgekeerd aan die van b.
  • e) fout. 220 Ω is de voorschakelweerstand van een led. Een pull-up of pull-down is veel groter, meestal 1 kΩ tot 10 kΩ. Zet je er 220 Ω neer, dan loopt er bij een ingedrukte knop onnodig veel stroom van +5 V naar de massa.

Vraag 3: multiplexing uitleggen (open vraag)

Je toont een getal van 00 tot 99 op een dubbel 7-segment display.

  1. Leg uit waarom je de twee cijfers niet tegelijk kan tonen, en hoe multiplexing dat oplost.
  2. Je wil je teller elke seconde ophogen en schrijft daarvoor delay(1000) in je loop(). Wat gaat er mis, en hoe los je het op?

Deel 1

Een dubbel display bevat twee 7-segment displays, en hun zeven segmentaansluitingen zijn intern aan elkaar geknoopt: segment a van het linkse en segment a van het rechtse hangen aan dezelfde pin. Dat spaart pinnen uit, maar het betekent ook dat een patroon dat je op de segmentpinnen zet, meteen naar allebei de displays gaat. Een 4 links en een 7 rechts tegelijk kan dus niet. Alleen de gemeenschappelijke pin van elk display is apart uitgebracht, en daarmee kies je welk display op dat moment stroom krijgt.

Multiplexing gebruikt dat: je zet het patroon van het linkse cijfer klaar, activeert alleen het linkse display, wacht even, zet dan het patroon van het rechtse cijfer klaar, activeert alleen het rechtse, wacht weer even, en begint opnieuw. Doe je dat traag, dan zie je de cijfers om beurten flikkeren. Doe je het snel genoeg, ongeveer vanaf 50 keer per seconde per display, dan kan je oog de twee niet meer scheiden en zie je gewoon twee cijfers naast elkaar. Dat komt door de persistentie van het netvlies: je oog blijft een lichtpunt nog een fractie van een seconde zien nadat het al gedoofd is. Precies dezelfde truc als bij film.

Deel 2

Zolang je programma iets anders doet, staat er geen enkel display aan. Met een delay(1000) in je loop blijft je display dus een volle seconde donker, en dan ziet de student een display dat kort oplicht en daarna uitgaat, niet een teller.

De oplossing is de tijd bijhouden in plaats van erop te wachten, met millis(). Je loop blijft dan gewoon doorlopen en multiplexen, en telkens je erlangs komt kijk je of er al genoeg tijd voorbij is:

void loop()
{
  multiplexStap(teller / 10, teller % 10);

  if (millis() - vorigeTick >= 1000)
  {
    vorigeTick = millis();
    teller = (teller + 1) % 100;
  }
}

Vraag 4: de voorschakelweerstand berekenen (numeriek)

Je sluit een led aan op een uitgang van 5 V. In de datasheet van die led vind je:

  • Vforward = 2,1 V
  • Iforward = 15 mA

Bereken:

  1. De theoretische waarde van de voorschakelweerstand, in ohm.
  2. Welke weerstand je in de praktijk neemt, en waarom die kant op.
  3. De stroom die er dan echt loopt, in milliampère.

1. Ongeveer 193 Ω

De led neemt 2,1 V van de 5 V voor zijn rekening. Wat overblijft, staat over de weerstand. Reken met ampère, niet met milliampère: 15 mA is 0,015 A.

$$ R = \frac{V_{CC} - V_{forward}}{I_{forward}} = \frac{5\,\text{V} - 2{,}1\,\text{V}}{0{,}015\,\text{A}} = \frac{2{,}9}{0{,}015} \approx 193{,}3\ \Omega $$

2. 220 Ω, dus naar boven afgerond

193 Ω bestaat niet als losse weerstand in je kit. Je rondt altijd naar boven af: een grotere weerstand geeft minder stroom, dus een iets minder felle maar veilige led. Naar beneden afronden doet het omgekeerde, en dan trek je meer stroom dan de datasheet toelaat.

3. Ongeveer 13,2 mA

$$ I = \frac{U}{R} = \frac{5\,\text{V} - 2{,}1\,\text{V}}{220\ \Omega} = \frac{2{,}9}{220} \approx 0{,}0132\ \text{A} = 13{,}2\ \text{mA} $$

Dat is ruim onder de 20 mA die je per pin veilig aanhoudt, en genoeg om de led goed te zien branden. Deze controle achteraf is de moeite: zo weet je of je afronding klopt.

Vraag 5: zoek de twee fouten (code)

Een student wil met een potentiometer de helderheid van een led regelen. De schakeling is correct gebouwd volgens de code, maar de led springt gewoon van uit naar volle sterkte in plaats van mooi te dimmen.

const int potPin = A0;
const int ledPin = 7;

void setup()
{
  pinMode(ledPin, OUTPUT);
}

void loop()
{
  int waarde = analogRead(potPin);
  analogWrite(ledPin, waarde);
}

Er zitten twee fouten in. Welke, en hoe los je ze op?

Fout 1: pin 7 kan geen PWM

Alleen de pinnen met een ~ ernaast kunnen PWM: op de Uno en de Leonardo zijn dat pin 3, 5, 6, 9, 10 en 11. Pin 7 zit daar niet bij. Roep je analogWrite() aan op een gewone digitale pin, dan gedraagt die zich als digitalWrite(): alleen volledig aan of volledig uit. Precies wat de student ziet.

Oplossing: verhuis de led naar een PWM-pin, bijvoorbeeld pin 3.

Fout 2: de twee bereiken komen niet overeen

analogRead() geeft een waarde van 0 tot 1023 (10 bits), maar analogWrite() verwacht een waarde van 0 tot 255 (8 bits). De waarde wordt dus niet herschaald. Alles boven 255 loopt over en de dimming klopt niet.

Oplossing: herschaal met map(), of deel door 4 (1024 / 256 = 4).

const int potPin = A0;
const int ledPin = 3; // PWM-pin

void setup()
{
  pinMode(ledPin, OUTPUT);
}

void loop()
{
  int waarde = analogRead(potPin);
  int helderheid = map(waarde, 0, 1023, 0, 255);
  analogWrite(ledPin, helderheid);
}
